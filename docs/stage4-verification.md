# 四期实现与 Mac 验收

日期：2026-10-19。范围对应 `todo/stage4.md`。环境：macOS 15.3.2、Apple Silicon / arm64，使用仓库锁定依赖。验收覆盖 Rust core、SQLite、现有宿主的模拟测试、HTTP harness 和 Chromium；没有新增 Mac 桌面宿主。

## 实现

| 能力 | 实现与边界 |
| --- | --- |
| 英雄笔记 `/notebooks` | 按稳定英雄 ID 保存多条笔记、连招、对阵经验和出装。无账号、无战绩也可创建；全英雄目录沿用本地名称表，头像按需读取缓存。搜索、置顶、双方英雄、位置、标签、自由正文及显式保存可用。界面中英文切换不会改写用户内容。 |
| 草稿与冲突 | 草稿按工作区和条目隔离，跨页面保留；关闭编辑器可保留草稿，丢弃需确认。保存期间禁用输入，修订冲突和保存失败保留正文；冲突可另存为新条目。恢复工作区不会把旧草稿自动写入新库。 |
| 连招与出装编辑 | 连招可选择 Q/W/E/R、普攻、移动、召唤师技能、装备或文字动作；标注支持 Q1/Q2，步骤可插入、删除、按按钮或键盘重排。出装使用带图搜索、数量和有序可重命名分组；支持复制与从实际对局创建待确认草稿。不会执行连招或购买装备。 |
| 修订与回收站 | 每次成功保存记录不可变修订。恢复历史生成新修订；软删除、恢复和永久删除保留其余知识及练习记录，永久删除需确认引用影响。循环关联只作为链接打开，不递归展开。当前链接读最新修订，历史链接固定保存时的修订。 |
| 来源与复核 | 对局、报告、证据来源固定，来源消失不删除用户正文；失效来源明确显示不可用。适用补丁、资源版本、内容修订和规则版本分开保存；编辑后待复核，只有用户明确确认才确认当前修订。 |
| 赛前速查与练习 | 用户主动展开速查，按当前英雄和公开对手筛选，置顶优先；不自动打开编辑器或应用出装。换英雄、选人取消、比赛代次及会话变化更新上下文。手动练习状态和心得单独存储，来源更新显示变化，不参与数值目标评估。 |
| 单英雄交换 | `riftmind-champion-notebook` v1 JSON 与客户端装备方案格式不同。导出预览有效条目，排除历史、回收站、练习心得、对局私有来源和客户端映射。导入限制 4 MiB / 500 条、校验结构和 ID；默认跳过重复、同名另存，显式替换保存旧修订；内部 ID 重映射，单事务提交。 |
| 客户端装备方案 | 单独导出兼容字段；通过明确的目标资源版本校验装备 ID、地图、购买状态。生产客户端适配未经实机验证，写入门禁关闭；本地保存与 JSON 导出独立可用。模拟适配完成身份、阶段、会话、工作区、UID 映射、完整集合合并、外部修改冲突和写后读回检查。超时先对账，不按标题匹配或删除客户端其他方案。 |
| 事件上下文 | 固定报告、输入修订与证据。默认前后各 60 秒，可调整至各 600 秒；裁剪比赛边界，提供本人死亡、资源事件、全部事件及前后导航，联动曲线和证据。参与英雄、装备与技能使用对应图片；敌方打野仅在可靠位置集合下标记参与，不推断意图或因果。缺帧保留断点。 |
| 个人历史基准 | Rust 计算并保存固定比较快照。默认同玩家、队列、位置、补丁、英雄，可明确改为同位置全部英雄；只用早于当前对局的本地记录。每项最多最近 20 个有效样本，至少 5 场显示中位数、四分位及差值；逐项保留入选/排除原因和报告修订，显式刷新才换样。ECharts 展示四分位范围与本场值，并保留数值表。 |
| 训练范围与趋势 | 可选英雄约束贯穿草稿、选样、冻结基线、后续评估、修改范围和备份；来源选定英雄时默认相同范围。旧目标缺少该字段仍解释为全部英雄，来源筛选不反向变成约束。范围、方向、补丁或阈值变化产生新目标版本；逐场趋势、目标线和后端冻结基线配数值表，旧评估可回看。新报告仅自动刷新符合范围的活动目标。 |
| 有限准备批次 | 显式选择最多 20 场，预览后固定集合。复用详情/报告任务、去重和来源策略，串行处理，低于每服务最多 2 并发的上限。本人远端详情门禁保留，离线可用已有输入。逐场持久化结果，取消停止后续项；401/403/429 停止剩余请求，遵守冷却。批次归属阻止子任务重启自动续跑，用户继续时重新检查身份与工作区；已有报告不重复生成。 |
| 存储与生产隔离 | 新增 `0004_champion_notebooks.sql`、`0005_review_training_insights.sql`，同步 core、宿主及 harness。支持旧库/旧备份升级至 v5；带 `_sqlx_migrations` 的桌面备份同时升级 SQLx 登记与 user_version，恢复后不会重复执行建表。恢复验证嵌入引用，不重放远端写入。前端仅经 Rust 生成的 typed transport；生产包检查排除 fixture、harness、开发工具栏及测试图片。 |

### 资源与客户端契约

装备图片仍使用现有 CommunityDragon 图片链路。地图和购买状态来自固定完整版本的 [Riot Data Dragon 装备目录结构](https://ddragon.leagueoflegends.com/cdn/15.1.1/data/en_US/item.json)，分别读取 `maps` 和 `gold.purchasable`；该链接只作为结构依据，不是目标版本的回退源。CommunityDragon 的装备列表没有可依赖的地图字段，不能据此假定所有地图可用。资源版本不存在、未缓存或字段不足时拒绝导出/应用，不改用 `latest`。

装备目录缓存位于独立资源根的 `catalogues/`，与内容修订分开；固定官方来源、限长响应、禁重定向、路径校验和原子写入。测试目录和真实资源目录隔离。

模拟装备集合契约为 `{ itemSets: [...], ...unknownFields }`，测试使用合成身份和 UID。实际 Riot/Tencent 版本与区服尚未采集响应，不能把模拟成功解释为真实客户端可用。整体集合 PUT 没有条件锁，重新读取和串行化只能缩小其他程序并发修改的窗口，不能消除该窗口。

### 统计与训练语义

- 个人基准算法：`personal-history-1:type7:round3:recent20:min5:scan10000`。按开始时间降序、对局 key 降序扫描最多 10,000 场；逐指标选最近 20 个有效记录。四分位采用 type 7 线性插值，展示值和差值四舍五入到小数点后三位；快照保存成员、报告及输入修订，晚到数据不替换既有快照。
- 新训练评估算法版本为 `3`，旧版本评估保持原值与成员。基线/后续各最多 10 场、至少各 5 场才给数值达标结论；达到阈值不自动完成目标。
- 沿用原有暂停语义：恢复活动状态重新设置 `windowStart`，恢复前的对局不进入新窗口；暂停前评估仍可按修订查看。新报告自动评估经过英雄和其他范围校验，不会因其他英雄的新报告创建无关评估。
- 独立人工预期：`[10,20,30,40,50]` 的 Q1/中位数/Q3 为 20/30/40；`[10,20,…,250]` 最近 20 场为 60 至 250，Q1/中位数/Q3 为 107.5/155/202.5。这些值没有从当前实现生成。

## 验收入口与结果

```sh
bun run verify:stage4
```

依次执行项目格式/TypeScript/ESLint/翻译/主题/shadcn/契约/fixture 检查、前端单测、Rust core 与既有宿主模拟测试、Rust 格式与 Clippy、全部浏览器 E2E、生产构建和隔离检查。报告及日志写入 `.tmp/verification/`，截图和 trace 位于 `.tmp/browser/` 与 `.tmp/playwright/`；`.tmp/` 保持 Git 忽略，Vite 不监听该目录。

已通过完整入口：前端 **37** 项单测、Rust core **67** 项测试、宿主 **3** 项模拟测试、浏览器 **16** 项 E2E，以及检查、格式、Clippy 和生产构建。完整入口通过后，对训练自动刷新范围、中文保存流程和旧桌面备份恢复追加了对应测试及复验；core 由 66 项增至 67 项。结果见同目录的 `final-rust-tests.log`、`notebooks-tests.log`、`notebooks-e2e.log` 与 `project-check.log`。

新增验证包括无战绩英雄编辑与离线重启、修订冲突、历史恢复、回收站、来源删除、SQL 事务中途失败回滚、循环关联重映射、重复导入、补丁确认、英雄训练约束与旧目标语义、模拟出装保留未知字段/幂等/超时对账/阶段门禁、20 场批处理取消/继续、401/403/429、重启不自动获取详情，以及导入/速查/恢复不会写入客户端。

界面使用 shadcn 组合，沿用既有主题、字体与侧栏。已检查英文浅色和中文深色的笔记、连招、出装与复盘页面，包含 800×600 窗口；正文安全显示、图片位置、键盘步骤重排和模态内选择器均有覆盖。搜索弹层挂载在所属模态框内，避免被焦点和辅助技术隔离；图表错误保留数值表和笔记编辑。

## 未验证边界

真实 Riot/Tencent 客户端响应、权限、装备方案导入及商店可见性尚未实机验收，生产写入能力保持关闭。Windows 原生窗口、安装、签名发布、WebView2 下载对话框与物理设备操作未验证。本期没有发布生产包，也没有以模拟结果提升这些能力的验证等级。
