# 三期实现与 Mac 验收

日期：2026-10-19。范围按 `todo/stage3.md`；基于二期的 Tauri / React / Rust core / SQLite / harness。此记录说明 Mac 开发链路，不表示 Windows 安装发布或真实 Riot/Tencent 客户端联网验收。

## 实现链路

| 能力 | 实现与边界 |
| --- | --- |
| 比赛 `/live` | Rust 会话快照携带 sessionEpoch、代次、修订、更新时间和失效状态。订阅建立及重连时触发快照对账；阶段读前后对账，通知促使重新读取权威快照，另有有限轮询。选人用“我方/对方”分组，只有 gameflow 的已知队伍使用红蓝标签。取消选人清空阵容；加载衔接、结束保留、断线标失效、重连和切号重新对账。 |
| 玩家资料 | 仅公开 PUUID；不反查匿名身份。段位与近期统计独立加载，带队列和样本数。最多采用最近 20 场摘要，按玩家/范围去重、最多三个并发、60 秒缓存；换英雄复用已有资料。单个失败保留其他玩家。无自动 DETAILS、长期同步任务或 Live Client Data 请求。 |
| 搜索与收藏 | 显式提交 Riot ID / 接口支持的名称；Rust 校验同区授权、稳定 playerKey、鉴权和冷却。其他玩家摘要同步复用任务和来源优先级；跨区及他人 DETAILS 门禁保留。收藏存入 SQLite，昵称变化不重复，取消只删关系，离线与重启可读。 |
| 英雄池 `/champions` | 按玩家、队列、位置、补丁、日期、英雄筛选本地缓存；按场次、胜率、KDA、CS/min、伤害占比排序。每项独立有效样本与排除原因。胜率排除重开/未知；零死亡不产生无限 KDA；CS/min、伤害占比是有效逐场值的算术平均。趋势按队列/位置/补丁分组；ECharts 场次图配数值表。点击英雄保留筛选进入战绩。 |
| 两场对比 `/compare` | 两侧分别固定玩家、对局、输入修订与报告；明确固定“无报告/无输入”。读已有报告或固定输入计算指标，单位/版本不同或缺失时不算差值。曲线共用经过时间尺度，短局结束后不补点。事件按需加载和分类，证据保留侧别/报告，支持换场和交换。补全仅由用户选择，更新后不自动改比较修订。 |
| 跨场问题 | 只读取本地已存报告，每场/玩家取明确的最新报告修订。按规则 ID、语义版本、队列/位置/补丁分组；一局多次命中只记一场，缺能力单列，零分母无百分比，少于五场标注不足。 |
| 训练衔接 | 支持可评估规则的目标草稿，保留筛选范围及固定报告/证据引用；用户确认方向和阈值后启用。继承基线/后续各最多十场、至少五场才数值评估、暂停恢复和旧评估保存。GoalScope 的可选 origin 兼容二期目标；评估算法版本为 2。 |
| 存储与契约 | Rust 统一生成 DTO/Commands；新增 `0003_players_insights.sql`、收藏与资料缓存，core、生产迁移注册、harness 同步。备份支持 v1/v2 升级至 v3，校验 SQL 与 JSON 引用；恢复不复活在线阵容。修复恢复期间活动维护任务短暂消失的竞态。 |

聚合每次最多读取最近 10,000 场/份报告，结果分页；页面显示缓存范围与截断状态，不表示完整生涯。时间线正文不随聚合返回前端。网络请求不占 SQLite 写事务。查询缓存使用 workspaceEpoch、玩家、会话或输入修订，恢复会清理旧工作区缓存。

代码按业务拆分为 `live`、`players`、`champions`、`comparison`、`analysis` 与 `progress`，国际化使用 `scouting` 业务命名空间。阶段编号只保留在计划/验收记录及兼容的验收命令中。迁移源码改为业务名称，已存在的一/二期 SQL 内容不变。

英雄、装备、召唤师技能及英雄技能使用 shadcn Avatar 与 Rust typed resource 命令加载对应图片。英雄技能资源按英雄 ID 和 Q/W/E/R 槽位解析，拒绝非法槽位；无任意 URL 入口。选人未提供版本时，肖像使用与名称目录一致的固定 `16.20.1` 目录，不声称对应本场补丁。开发验收图片的固定 Riot Data Dragon URL 和哈希见 `tests/fixtures/ui-art/entity-sources.json` 与 fixture manifest，预览图片不进入生产包。

## 规则与样本

新规则语义版本均为 `1`，报告规则集合版本 `3.0`，转换器保持 `2.1`：

- `gold_deficit_10`：可靠对位、具备十分钟帧且经济差小于零，单局值为 0/1。
- `death_before_objective`：本人死亡严格早于资源事件，间隔不超过 60,000ms，单局值为 0/1。完整事件能力不足时不输出零；不声称死亡造成资源损失。

`tests/fixtures/scouting/live.json` 与 `expected.json` 为人工构造，结合二期 SUMMARY/DETAILS 合成输入；来源、人工预期和 SHA-256 清单随仓库保存。Rust 导出的 `normalized.json` 只用于开发预览，不充当独立预期。

Akari 功能参考固定为提交 `56cdfde00e56148f4641d1a8cf86acb66e903124` 的当前对局模块；未移植其实现。接口响应样本为合成结构，不是客户端采集。公共端点不可用、权限不足、未找到及限流分别降级；真实 LCU 时间线等价门禁保持关闭。

## 检查入口

```sh
bun run verify:stage3
```

依次执行类型/lint、翻译/主题/shadcn 控件约束、生成契约与样本哈希、前端单测、Rust core、fmt/clippy、真实 harness E2E、生产构建及开发模块隔离。实际环境、命令退出码、时长、源码基点、工作区状态与性能保存在不提交的 `.stage3-report.json`。

Mac arm64，Bun 1.3.14，Rust 1.97.1，Chromium。最终检查全部通过：33 项前端单测、56 项 Rust 测试（资源 8、一期 18、二期 15、三期 15）、11 项浏览器 E2E，以及 fmt/clippy、构建和生产隔离。验证包含：

- Rust：阶段/代次、加载衔接、匿名、非五人阵容、晚到响应、断线重连、资料去重/慢请求隔离、403/429 与区域门禁、各指标分母、旧修订/缺失比较、报告去重/规则版本、训练来源、迁移和备份恢复。

- 真实 harness / SQLite / 模拟 HTTP / 浏览器 WebSocket：公开选人 → 资料 → 换英雄/匿名/取消 → 比赛/结束 → 搜索/收藏/他人战绩 → 英雄池 → 固定两场对比/事件 → 问题汇总 → 目标草稿与确认启用 → 备份恢复 → 进程离线重启。

## 性能与限制

本地合成库 10,040 场摘要、40 份带时间线报告，聚合热查询各 20 次 p95；浏览器八次阶段切换测量事件到 DOM 延迟。本次英雄池 p95 为 164.62ms，问题汇总 p95 为 15.36ms；阶段事件到 DOM p95 为 69ms（八次）。完整记录见 `.stage3-report.json`。英雄池有 10,000 场读取上限，场次图配完整当前页数值表。反复切换检查图表 DOM 的建立/移除，组件清理 ResizeObserver、主题观察器和 ECharts 实例；全局订阅随外壳清理。
