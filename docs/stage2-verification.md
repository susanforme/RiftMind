# Stage 2 实施与验证

日期：2026-10-19。基于 `4f11793` 加工作区现有一期改动和本次二期增量；没有提交、发布或构建 macOS 宿主。产品仍只发行 Windows。

## 已接通的业务链路

- Rust 权威契约和生成 TS；新增 SUMMARY/DETAILS、不可变分析输入、能力集合、版本化指标、证据、报告、笔记/反馈及训练 Commands。
- `0002_review_training.sql` 为独立增量迁移。一期迁移没有因二期升级而修改；旧快照可在本地重建结算输入，时间线仍标缺失。生产 SQL 插件、core 与 harness 注册同一迁移。
- 页面实际打开后只对当前玩家、同区且缺数据的对局尝试一次自动补全；列表、悬停、预加载及焦点恢复只读本地。SUMMARY 优先使用有效缓存，DETAILS 独立授权/能力判断；403/429 不换源，失败有持久化冷却。
- 同步、详情、报告和评估分别去重。远端任务在会话切换/恢复时重新校验；本地报告可离线生成；取消保留已提交数据；中断任务通过固定请求恢复。
- 核心指标采用独立人工预期：零死亡 KDA 不输出无穷大，CS 不以零填补缺项，团队占比需要完整分母，10/15 分钟取此前最近且最多偏差 60 秒的帧，对位要求可靠且唯一。
- 显式规则注册声明所需能力和补丁范围。当前规则只描述原始事实，适用于各补丁；共用 420/440、地图 11、CLASSIC 闸门。缺能力跳过对应规则；所有观察具有固定输入的证据；最多三项行动，不输出段位/因果判断。
- `/matches/$matchKey/review` 提供结算、完整度、生成/重算/取消、证据定位、个人/对位曲线和数值表、事件分类、笔记、反馈和用户确认的目标。
- `/progress` 提供玩家、队列、位置、补丁、日期筛选及按可比组分开的趋势数值；目标支持草稿、启用、暂停、恢复、完成、放弃和新阈值版本。基线/后续各取最多 10 场，至少 5 场才有数值评估；旧评估与成员报告链接保留。
- 笔记、反馈和目标使用乐观锁；冲突保留草稿，提供重新读取修订的入口。证据笔记固定原报告，重算不转移；恢复备份后旧草稿留在原 workspaceEpoch 下，仅供复制。
- 备份包含二期表，支持一期备份升级，验证内容哈希、SQL 外键及 JSON 内嵌的报告/证据/训练成员引用。图片清理不删除业务证据。

## 样本、口径与来源

`tests/fixtures/review/sgp.json`、`lcu.json` 是分别按两种结构构造的合成输入，包含 10 位参与者、31 组帧、8 个事件及购买/出售/撤销/技能事件。测试派生缺帧、未知事件、串局、参与者错配、错误时间、重复时间戳和 HTTP 失败。

`expected.json` 与目录 README 保存人工算式；转换器测试与手工构造规范输入的指标测试分开。`normalized.json` 是 Rust 导出的开发预览事实，不用作人工正确答案。SHA-256 记录在 `tests/fixtures/manifest.json`；当前转换器/规则版本为 `2.1`，装备语义引用为空时明确降级到事件和装备 ID。

这些输入没有真实凭证或实机采集记录，不能作为国服/外服接口已验证的证据。SGP 路径依据仓库架构中的接口约定。真实 LCU 时间线等价能力尚未确认，生产适配器保持门禁关闭；独立样本和可验证能力适配器测试覆盖同区回退策略。

## 自动检查

环境：macOS arm64，Bun 1.3.14，Rust 1.97.1，Playwright Chromium。运行：

```sh
bun run verify:stage2
```

入口依次检查类型、lint、翻译与主题、样本哈希、生成契约、前端单测、Rust 测试、fmt、clippy、真实 harness E2E、生产构建与隔离。结果写入根目录 `.stage2-report.json`，包含源码基点、各命令退出码/耗时、Mac 性能样本和明确的未验证平台字段；报告文件不纳入 Git。

覆盖范围：

| 层次 | 用例与结论 |
| --- | --- |
| 前端单测 | 10 项：保留原 6 项，并验证修订/证据定位参数、显示口径、工作区草稿隔离、Rust 事实的 fixture 离线笔记 |
| Rust 一期 | 18 项回归，含 1 万场摘要列表、鉴权边界、恢复和资源缓存；另有当前资源缓存实现的 7 项回归一并通过 |
| Rust 二期 | 15 项，覆盖独立指标预期、转换、缺帧、模式/分路/提前结束、确定性证据、任务去重/取消/重启、403/429/端点能力回退、真实一期迁移及一期/二期备份、冲突、旧修订、目标窗口/版本及损坏引用拒绝 |
| E2E | 8 项：原 4 项回归、资源代理离线重启回归；完整训练闭环和离线进程重启；列表不请求详情及无效旧报告深链；图表加载异常不阻断报告和笔记 |
| 生产隔离 | fixture、review-fixture、harness、测试图片和开发工具栏不进入生产前端包；无通用前端 SQL/Shell/文件能力 |

完整闭环 E2E 经真实 Rust / SQLite / 模拟 HTTP 完成：同步 → 五场补全与报告 → 证据 → 笔记和反馈 → 确认目标 → 新五场可比输入 → 评估 → 备份恢复 → 进程重启离线阅读与写笔记。

## UI 审阅与边框修正

按项目 `frontend-design` 技能复核，沿用原有冷灰/白/蓝的 Windows 工作区外壳。全部控件仍组合 shadcn/ui；Table、Textarea、Skeleton 由官方 CLI 添加，ECharts 6.1.0 仅负责图表。

发现的问题是缺少 shadcn 基础层的 `border-border` 约束，Tailwind 4 的 `currentColor` 默认值让表格行、描边 Badge、弹层等继承了深色文字颜色。已补全全局 base 层并在共用 Card/Table/Badge/Select/Alert/DropdownMenu 中显式使用语义边框；不是只对单页卡片覆盖。

同时将复盘概况整理为英雄/结算信息和分开的状态/操作区；指标使用轻分隔线而不是一组实心色块；观察保留简洁的优先级与证据入口，减少重复外框和描边按钮；数值表固定滚动高度。Card 的槽位、标题字级、内容间距统一，保留键盘焦点。

浏览器检查覆盖简中/英语、浅色/暗色、800×600、原页面与复盘/进展页、弹窗、图表异常。E2E 检查实际可见边框没有回退为正文颜色，截图需要人工图像审阅；稳定审阅截图保存在 `docs/ui-review/stage2/`。
