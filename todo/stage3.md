# 三期计划：当前比赛、玩家查询与多场分析

状态：已实现并通过 Mac 开发链路验收。日期：2026-10-19。详见[三期验收记录](../docs/stage3-verification.md)；真实客户端接口仍未实机验证。

在[二期复盘与训练闭环](stage2.md)基础上，新增比赛页、玩家搜索与收藏、英雄池分析、两场对局对比和跨场问题汇总。二期实际验证边界见[二期验收记录](../docs/stage2-verification.md)，基础技术约束见[架构设计](../docs/architecture.md)。

**本期全部开发与验收在 Mac 上完成，不安排 Windows 原生验收、安装发布或签名更新，也不接入 AI。比赛页展示当前对局状态、阵容和参赛玩家资料，不采集或展示本场持续变化的击杀、经济、装备等局内数据。**

## 1. 交付目标与范围

用户能够在选人和比赛过程中查看当前阵容及参赛玩家的历史表现，打开玩家战绩或收藏玩家；赛后通过英雄池、两场对比和跨场问题汇总发现值得复盘的对局，并衔接现有训练目标。

| 本期必须交付 | 本期不交付 |
| --- | --- |
| 比赛页：阶段变化、公开选禁信息、双方阵容、玩家资料与近期战绩 | 本场实时击杀、经济、装备、实时战斗事件或实时数据曲线 |
| 同区玩家搜索、战绩查询、收藏与快速访问 | 跨区远端玩家查询、后台多账号批量同步 |
| 基于本地战绩的英雄池分析 | AI、模型配置、付费调用、聊天、自动生成教练解释 |
| 两场已结束对局的结算、曲线与事件对比 | 视频、ROFL 解析、局内浮窗、自动选禁、自动发消息 |
| 跨场问题汇总与训练目标草稿 | 无依据的综合评分、段位百分位、玩家意图或失误原因推断 |
| Mac 上 core、SQLite、模拟远端、harness 和浏览器完整验证 | Windows 原生验收、打包发布、生产签名与更新托管 |

QQ101 是可选后续扩展，不作为本期前置条件或完成标准，不为其预建空表、开关或占位界面。

本期不改变产品既定发行平台，也不新增 macOS 桌面宿主适配。Mac 使用现有开发链路验证业务实现；真实客户端联网能力按实际证据记录，不将模拟验证标记为实机验证，也不以 Windows 环境缺失阻塞本期完成。

## 2. 工程与界面约束

- 复用 Tauri、React、Rust core、SQLite、Store、类型生成、任务和事件体系，不另建服务或数据库。
- Rust 是 DTO、Commands、错误和事件的唯一契约来源；前端不直连 LCU、SGP 或 SQLite。
- 所有 UI 组件组合现有 shadcn/ui；缺失组件通过官方 CLI 添加，禁止手写替代实现。
- 实施界面时结合项目 `ui-ux-pro-max` 和 `frontend-design` skills，沿用侧栏、顶部标签、浅色/暗色/跟随系统以及简中/英语。
- 遵守 UI Content Minimalism：只保留指标、筛选、动作、必要状态与错误消息，不增加介绍段落或装饰性文案。
- 延续 Query 保存查询结果、Router 保存定位参数、Zustand 保存临时 UI 状态的分工。
- `desktop / fixture / dev-harness` 使用同一业务契约；生产构建继续排除开发工具、模拟数据与桥接代码。
- 确定性教练分析继续沿用二期支持的队列、地图和模式限制。比赛阵容可按数据能力展示其他模式，不将所有模式强制布局为 5 对 5 或套用排位分析规则。

## 3. 比赛页

### 3.1 页面与信息范围

新增侧栏“比赛”，建议路由 `/live`。历史对局仍留在现有对局页。比赛页按双方队伍组织玩家信息，并在布局紧张时分组换行；玩家位置不可靠时保持原始席位顺序，不猜测对位。

| 阶段 | 展示与交互 |
| --- | --- |
| 客户端未连接 | 连接状态和已有连接操作入口 |
| 房间、匹配、等待确认 | 当前阶段；尚无阵容时不显示上一局玩家 |
| 英雄选择 | 模式、公开选禁英雄、公开玩家身份和位置，跟随选人变化更新 |
| 加载中、比赛中 | 双方阵容、英雄、可获取的召唤师技能、身份和位置，以及独立加载的玩家历史资料 |
| 比赛结束 | 保留本场阵容并标记结束；结算入库后提供本场战绩与复盘入口 |

玩家资料包括可获取的当前段位、近期胜负、近期 KDA、常用英雄和当前英雄近期表现。每项历史统计标明队列范围与有效样本数；默认最多取最近 20 场摘要，具体字段缺失不以零代替。

- [x] 当前玩家突出显示；点击玩家可打开其战绩标签，支持收藏。
- [x] 英雄变化只更新相关英雄统计，不重复获取整个阵容的战绩。
- [x] 匿名选人、未公开身份与不可访问玩家保持缺失状态，不尝试反查隐藏身份。
- [x] 历史表现明确标为“近期”或“近 N 场”，不冒充本场实时指标；当前段位不冒充历史比赛段位。
- [x] 单个玩家资料失败、无段位或无历史记录，不阻断其余阵容。
- [x] 不为比赛页引入游戏内 Live Client Data 接口、本场 KDA/经济/装备轮询或实时战斗事件订阅。

### 3.2 状态与请求生命周期

复用当前客户端连接与会话管理，新增明确的当前比赛领域状态。已有 gameflow phase 请求入口不等于已经具备阵容、选人和玩家资料能力；实施时分别核实所需端点、响应和事件。

- [x] 建立初始快照与事件订阅的对账流程，避免读取快照期间漏掉状态变化；重连重新获取权威快照。
- [x] 应用中途启动或页面重新打开时能恢复当前阶段；页面切换不重复注册全局订阅。
- [x] 当前状态携带 sessionEpoch 和比赛代次。选人未产生 game ID 时也有本地代次；同一局从选人进入比赛需要可靠衔接。
- [x] 取消选人、重新匹配、切号、切区和新比赛开始时清理旧阵容，取消或忽略旧请求；旧响应不得写入新代次。
- [x] 客户端断开后保留的快照标为失效，不继续呈现为正在实时更新；重新连接后以新快照对账。
- [x] 退出选人与比赛结束分别处理。结束后不抢占用户当前标签，不自动打开复盘。
- [x] 结算尚未入库时显示等待状态；复用有上限的赛后同步策略，超出预算保留手动重试入口。
- [x] 玩家资料与摘要查询按区服、玩家和查询范围去重，遵守现有鉴权、有限重试、限流和冷却策略。
- [x] 自动读取参赛玩家的少量资料和近期摘要，不批量下载这些玩家的 DETAILS，也不自动建立长期同步任务。

Akari 功能参考：[当前对局模块](https://github.com/LeagueAkari/LeagueAkari/blob/dev/src/main/shards/ongoing-game/index.ts)、[比赛面板](https://github.com/LeagueAkari/LeagueAkari/blob/dev/src/renderer-shared/components/ongoing-game-panel/OngoingGamePanel.vue)。实施前固定所参考的提交和接口样本；直接移植代码时保留相应许可声明。本项目界面仍按自身技术栈与 shadcn/ui 约束实现。

## 4. 玩家搜索与收藏

在对局页增加搜索与收藏入口，并与比赛页共用玩家查询和标签逻辑。

- [x] 以区服和稳定玩家 ID 标识对象，不用显示昵称作主键；按接口能力支持 Riot ID 等有效查询格式。
- [x] 首版只查询当前会话支持的同区玩家，保留未知区服、未登录、权限不足、未找到和限流等独立状态。
- [x] 搜索由显式提交触发；过期搜索结果不覆盖更新后的查询结果。
- [x] 从结果打开玩家战绩标签；同一玩家同一区服复用既有标签，不改变当前登录账号身份。
- [x] 战绩按页读取，复用来源优先级和禁止跨区回退规则；扩大查询范围时在 Rust 端校验授权边界，不能只解除前端限制。
- [x] 收藏持久化到 SQLite，按区服与玩家键去重；昵称变更不创建重复收藏。
- [x] 取消收藏只移除收藏关系，不删除已缓存的战绩、报告或笔记。
- [x] 离线时仍可访问收藏和本地战绩；收藏本身不触发后台同步。

从其他玩家战绩打开复盘时，先读取本地数据。远端详情仅在接口能力与授权明确支持时由用户主动请求；不能把可查询摘要等同于可读取 DETAILS。

## 5. 英雄池分析

新增侧栏“英雄池”，建议路由 `/champions`，基于选定玩家的本地缓存提供统计，不要求外部统计服务。

- [x] 支持玩家、队列、位置、补丁和日期筛选；点击英雄进入保留筛选条件的战绩列表。
- [x] 展示英雄场次、胜率、平均 K/D/A、可用的补刀指标、伤害占比及近期趋势；支持按场次或指定指标排序。
- [x] 每个指标返回自身有效样本数和排除原因，不能用全部场次数掩盖部分字段缺失。
- [x] 胜率分母为胜负明确且符合筛选条件的非重开对局；重开与结果未知单列排除数量。
- [x] KDA 沿用二期单局口径：零死亡不输出无穷大，平均 KDA 仅统计可用比例并显示有效样本数；平均 K/D/A 可独立展示。
- [x] CS/min 和伤害占比使用已有版本化指标，明确采用逐场值的算术平均；缺少必要详情时只统计已有有效样本。
- [x] 位置未知单独归组；不同队列、位置与补丁的趋势不混成同口径结论。
- [x] 显示本地缓存覆盖范围；统计不能声称代表玩家完整生涯。
- [x] 打开页面只做本地聚合，不扫描历史批量补拉 DETAILS；图表继续使用 ECharts 并提供数值表。

## 6. 两场对局对比

在战绩列表增加“两场对比”选择流程，选择恰好两场不同的已结束对局后打开对比标签。建议路由 `/compare`，URL 和标签状态分别固定两侧的 matchKey、playerKey 及所选报告/输入修订。

首版以同一玩家两场比赛为主；可选择不同英雄、队列或补丁进行人工查看，但必须标明差异，不自动形成优劣结论。

- [x] 并排展示结算、可用指标与差值；单位或指标版本不兼容时不计算差值。
- [x] 经济、补刀等曲线按比赛经过时间对齐，时间轴使用统一尺度；较短比赛结束后留空，不外推、不补零。
- [x] 已结束对局的出装事件、技能和资源事件可按类别查看，复用现有时间线及证据读取能力；这不属于比赛页的局内实时采集。
- [x] 两侧可以独立缺少详情、报告或某项能力，已具备的数据继续显示。
- [x] 按需补全复用二期任务与授权规则，只有用户选中的两场进入处理范围。
- [x] 证据跳转固定对应侧、报告修订和事件；重算产生新报告时不静默切换正在对比的版本。
- [x] 支持交换两侧和替换单场；关闭标签释放图表及订阅，不影响已有笔记。

## 7. 跨场问题汇总与训练衔接

在进展页增加跨场问题汇总，回答哪些已被规则识别的情况反复出现、出现在哪些对局，以及采用训练目标后对应指标如何变化。使用确定性计算，不依赖 AI。

### 7.1 汇总口径

- [x] 按玩家、队列、位置、补丁、日期及可选英雄筛选，仅使用已保存且符合条件的报告。
- [x] 同一对局与目标玩家只纳入一个明确选定的有效报告修订；重算后的多个报告不能重复计数。
- [x] 按规则 ID、规则版本和可比条件分组，不按翻译后的文案字符串合并；不同语义版本不直接合并。
- [x] 每项返回命中对局数、具备该规则所需能力的有效对局数、缺失/不适用数及对应报告证据。
- [x] 出现率按“命中对局数 / 有效对局数”计算，一局多次命中只计一次；若展示事件次数则单独标注。
- [x] 零分母不显示 0%；少于 5 场有效样本时可展示记录，但标注样本不足，不形成稳定趋势判断。
- [x] 汇总读取本地报告，不为凑样本自动下载历史 DETAILS 或批量生成所有报告。

首批候选包括可靠对位下的 10 分钟经济落后、资源事件前指定窗口内死亡等可核验事实。先核对已有规则能否支持；缺少对应规则时补充版本化规则、能力要求和人工预期，再开放该汇总项。时间上的先后关系不表达为死亡导致资源丢失，不推断视野、操作失误或玩家意图。

### 7.2 训练目标

- [x] 用户可从支持训练的汇总项创建目标草稿；来源保存规则、筛选范围及固定报告引用。
- [x] 仅对已有可计算指标或本期明确实现的可评估指标提供创建入口，不把任意观察文案直接变成目标。
- [x] 目标由用户确认范围、方向和阈值后启用，不自动修改已有目标。
- [x] 保留二期基线/后续各最多 10 场、至少 5 场才形成数值评估、暂停恢复和版本化规则。
- [x] 本期新增的英雄限定、规则发生率等范围若超出现有 GoalScope，必须一并扩展契约、评估算法版本、迁移和旧目标兼容，不能静默丢弃筛选。
- [x] 对比训练前后时展示样本与排除原因，不宣称训练造成变化；可跳转到参与评估的具体报告和证据。

## 8. 契约、持久化与一致性

S3-0 核对当前契约、服务和迁移后确定字段。以下是职责边界，不要求预先创建全部新表。

| 数据 | 归属与约束 |
| --- | --- |
| 当前比赛、选人、阵容 | Rust 会话态快照与事件；含代次、更新时间和字段可用性，不作为历史结算写入战绩库 |
| 玩家身份、段位及近期摘要 | 带区服、来源、采集时间的资料/缓存；与当前登录身份分离，段位不写成历史对局段位 |
| 收藏 | SQLite 持久化；工作区隔离，备份恢复覆盖 |
| 英雄池及跨场聚合 | 本地查询或可失效派生缓存；结果标明输入范围、规则版本及样本数，不建立另一份事实来源 |
| 对比定位 | Router 和已有标签持久化结构；固定对象及输入/报告修订 |
| 训练来源与扩展范围 | 随目标版本保存，兼容二期目标与历史评估 |

- [x] 需要结构变化时新增 `0003_players_insights.sql`，不修改一期、二期已发布语义；同步 core、生产注册和 harness。
- [x] Commands 按用途提供当前比赛快照、玩家搜索/资料、收藏、英雄统计、对比与问题汇总查询；不提供任意路径、URL 或通用数据库入口。
- [x] 实时事件与查询快照可对账；UI 乱序、漏事件或重载后能恢复权威状态。
- [x] Query key 和异步任务包含必要的工作区、区服、玩家及输入版本，防止切号或恢复备份后串数据。
- [x] 聚合查询分页/限量返回，不将全部原始时间线加载到前端；网络不占用 SQLite 写事务。
- [x] 备份包含收藏、持久化资料及训练来源引用；恢复校验对象关系，支持旧备份升级，当前在线状态不从备份复活。

## 10. Mac 测试与验收

### 10.1 场景矩阵

| 范围 | 必须覆盖 |
| --- | --- |
| 比赛状态 | 未连接、匹配、选人、换英雄、取消选人、加载、比赛中、结束、结算延迟、中途启动 |
