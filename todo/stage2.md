## 1. 交付目标与范围

用户从已缓存的对局进入复盘，按需补全结算和时间线，查看能够追溯到原始数据的指标与建议，记录笔记和反馈，选择训练目标，并在后续可比对局中查看进展。客户端关闭后，已经获取的数据、报告和用户记录仍可阅读和编辑。

| 本期必须交付 | 本期不交付 |
| --- | --- |
| 按需获取单局 SUMMARY / DETAILS、校验和持久化时间线 | 默认遍历历史列表批量下载所有 DETAILS |
| 复盘详情、时间线、经济/补刀曲线、证据定位 | 视频录制、ROFL 解析、逐帧还原、局内浮窗 |
| 确定性指标、规则观察、版本化报告 | LLM 接入、模型配置、付费调用、AI 聊天 |
| 复盘笔记、建议反馈、用户确认的训练目标与评估 | QQ101、段位百分位、无依据的综合评分 |
| 单玩家历史趋势、明确的样本数和可比性 | 玩家搜索、跨区远端玩家查询 UI、多账号批量同步 |
| 真实迁移、任务恢复、备份兼容和分层验收 | 云账号、云同步、反馈上传、主题市场 |

分析支持范围固定为召唤师峡谷单双排和灵活组排（队列 420、440，仍需同时校验地图和模式）。其他模式保留列表、结算及已有时间线阅读，显示“当前模式暂不支持教练分析”，不套用排位规则。重开局不进入训练统计；提前结束但非重开的对局按实际时长和能力逐项判断。

继续只发行 Windows 客户端。Mac 开发和验证 core、真实临时 SQLite、模拟远端以及浏览器页面，不增加 macOS 宿主支持。

## 2. 延续基座与本期工程约束

- 复用 Tauri 2、React、Rust core、SQLite、现有 Store、类型生成、任务与事件链路，不另建服务或数据库。
- **所有 UI 组件必须基于 shadcn/ui。** 优先组合 `src/components/ui/` 已有组件；缺少 Table、Textarea、Skeleton 等组件时通过 shadcn 官方 CLI 添加，禁止手动仿写。业务卡片、表单、时间线控制、状态与浮层均遵守此约束。
- 图表使用总体架构已选定的 Apache ECharts，仅负责数据可视化；外层卡片、筛选、标签、数值表和交互入口组合 shadcn/ui。实际接入时验证兼容版本并锁定，不在本计划阶段安装依赖。
- 延续左侧功能区、顶部多标签、default 浅色/暗色/跟随系统、简中/英语；不重新设计一期外壳。
- Rust 是 DTO、Command、错误和事件的唯一契约来源；沿用现有生成工具，不手写平行 TS 领域类型。
- domain 仅执行确定性转换和计算；services 组织网络、任务与事务；storage 不访问网络；前端不直接访问 SGP、LCU 或 SQLite。
- 保持 `desktop / fixture / dev-harness` 同一业务接口，生产产物继续排除模拟数据、测试图片和开发桥接。
- 沿用当前代码路由及 hash history，不为了二期改成另一套路由生成方式。Query 保存查询结果，Router 保存定位参数，Zustand 只保存临时交互和草稿。

### 2.1 必须处理的现有模型差异

以下来自当前源码，是实施起点，不能把总体架构中的目标模型当成已存在结构：

| 当前结构 | 本期处理 |
| --- | --- |
| `match_revisions` 以对局、玩家、revision 为主键，关联一个快照 hash | 保留一期语义；新增对局级不可变分析输入修订，固定结算、时间线、转换器与能力集合，不混用两种 revision |
| `source_snapshots` 以内容 hash 去重 | 增加对象/端点/来源/抓取时间的引用元数据；内容去重不能抹掉来源关联 |
| `jobs_active` 仅按 player_key 限制 queued/running | 改为按任务种类和业务去重键约束，允许同一玩家的同步与复盘任务共存，同时保留同步自身去重 |
| `JobKind` 只有同步、备份、恢复、诊断 | 增加详情补全、报告生成、目标评估；继续使用现有 Completed 等状态，不另建一套互不兼容的状态名 |
| 列表 DTO 只有目标玩家的摘要字段 | 分析模型独立容纳全体参与者、队伍和字段能力；不扩大每页列表返回体到完整详情 |
| 标签记录仅有 kind、playerKey、search 等字段 | 增量扩展并迁移可恢复的复盘/进展定位信息；旧 settings 和旧标签仍可读取 |

### S2-1：按需补全详情

1. 打开复盘页先读取本地结算、时间线状态和已有报告，立即展示可用内容。
2. 当前登录玩家、同一目标区服的对局缺少必要数据时，可在页面实际打开后提交一次去重的补全任务；路由悬停、预加载和恢复焦点只读本地。

4. 已有结算满足分析所需字段时不重复请求 SUMMARY；仅保存了精简投影时，优先从原始快照重新转换，仍缺字段才请求单局结算。
5. DETAILS 请求以目标对局规范键确定区服与 game ID，执行 SGP 优先和端点能力校验。不能用当前会话区服覆盖目标区服。
6. 按一期策略区分等待授权、401、403、404、429 与暂态网络错误。401 合并刷新一次；403/429 不换源；仅在允许的失败条件下使用已经验证等价能力的同区 LCU 回退。LCU 时间线能力不能由 SUMMARY 能力推导。
7. 任务显示阶段、进度、失败原因和重试入口；取消停在安全点，保留已提交数据。失败缓存保留冷却时间，页面重渲染不能形成请求循环。

- [ ] 校验 SUMMARY / DETAILS 的对局身份、参与者映射、时间单位、时间范围及基本结构；串局或基础身份损坏时拒绝入库为有效分析输入。
- [ ] 独立记录 summary/timeline 的 `missing / pending / partial / ready / unsupported / failed`；失败尝试与已有有效版本分别保存，刷新失败不能清空旧数据。
- [ ] 能力按内容计算：参与者结算、经济帧、补刀帧、可靠位置、击杀事件、资源事件、装备事件、技能事件等；请求 200 不代表所有能力可用。
- [ ] 未知事件保留原值并跳过不支持的分析，不让整局失败。事件按时间与稳定原始索引排序，证据保留原始位置；不以同毫秒、同类型作为去重依据。
- [ ] 旧 sessionEpoch 响应不得污染新会话；报告计算可以使用固定的本地输入继续执行，远端任务恢复必须重新校验会话。

## 4. 不可变输入、指标与报告

### 4.1 领域契约

| 模型 | 必须包含 |
| --- | --- |
| `MatchContext` | matchKey、目标 playerKey、参与者/队伍映射、队列/地图/模式、原始版本、实际时长、来源与输入修订 |
| `DataCapabilities` | 每种能力的状态、覆盖区间、缺失/不支持原因及校验结果 |
| `AnalysisInput` | 不可变输入 ID、结算/时间线快照引用、转换器版本、规范数据、能力集合；指纹由规范序列化内容确定 |
| `MetricResult` | 指标 ID/版本、单位、值或空值、分母、实际采样时间、`available / missing / not_applicable / unsupported`、原因 |
| `EvidenceRef` | 快照 ID、原始 JSON 路径或事件/帧索引、timestampMs、参与者；能校验属于该报告固定输入 |
| `Finding` | 稳定 findingId、规则 ID/版本、指标和证据引用、优先级、观察/建议文案 key 及参数、限制说明 |
| `ReviewReport` | reportId/报告修订、目标玩家、输入指纹、规则集版本、资源语义引用、指标、观察、缺失说明和生成时间 |

外部 ID 跨 IPC 仍为字符串。比赛内时间统一为毫秒，实际 duration 的现有秒字段在转换边界明确换算；日期存 UTC。计算保留精度，展示按单位舍入；不返回 NaN/Infinity。报告存结构化事实和可本地化文案，不因切换中英重新计算指标；旧规则对应的文案需要保留可读回退。

### 4.2 首批指标的固定口径

| 指标组 | 口径与缺失处理 |
| --- | --- |
| 击杀/死亡/助攻与 KDA | 展示原始 K/D/A；死亡大于 0 时 KDA = (K+A)/D；零死亡标记零死亡表现，比例为不适用，不输出无穷大 |
| 补刀与 CS/min | 线上补刀和野区补刀分别保存，总补刀为二者之和；除以实际比赛分钟。任一必要字段缺失不补 0；非正时长为不适用 |
| 参团率 | (K+A)/己方英雄击杀数；分母为 0 时不适用，队伍结算缺失时为 missing |
| 伤害/经济占比 | 对英雄伤害或总获得金币 / 同队完整参与者对应字段之和；缺队友字段不能以已知部分作为分母 |
| 10/15 分钟发育 | 使用目标时间之前最近一帧，最大偏差 60 秒，不插值；记录实际时间。比赛未到目标时间为不适用，已到但缺合适帧为 missing |
| 对位差 | 仅在位置映射唯一且可靠时比较同位置双方同一采样时间的经济/经验/补刀；不确定时展示个人值和无法对位原因 |
| 死亡与资源事件 | 展示真实时间、击杀/助攻参与者及资源顺序；只有可靠位置映射时才标识敌方打野。观察资源前后 60 秒内已有事件，明确这只是观察窗口 |
| 出装/加点 | 展示已知事件序列；撤销关联原购买/出售，无法关联时标注不确定；成装判断依赖该补丁静态语义，缺版本资料时只展示事件与装备 ID |

上述采样窗口是本产品首版规则参数，不是上游接口保证；调整必须升级对应规则版本。输入明显不合理时保留原始样本和异常原因，不静默截断成看似正常的数值。

### S2-2：确定性分析与证据

- [ ] 转换器测试与指标测试分开；先验证规范输入，再验证计算结果，防止两层错误互相抵消。
- [ ] 规则以普通 Rust 模块与显式注册表组织，声明模式、补丁范围和所需能力，执行 `supports → compute → validate → explain`。
- [ ] 先交付发育差、死亡事件、资源事件顺序、构建过程等能够定位事实的观察；建议使用可执行行动，不推断玩家意图、视野或操作失误。
- [ ] 不因落后、死亡或一次资源丢失直接给出因果结论；没有基准时不输出“优于同段位”“出装错误”等评价。
- [ ] 每条观察至少有一个有效证据，引用必须属于固定输入；单条规则缺数据只跳过该规则并说明原因，基础输入损坏才拒绝整场分析。
- [ ] 报告包含本场概况、可支持的正向表现、最多三项优先改进、时间点、下一局可执行目标、数据限制；没有依据的栏目允许明确为空，不凑建议数量。
- [ ] 同输入、规则和语义资源版本生成相同指标、观察及证据；时间戳和任务 ID 等运行元数据不参与内容一致性比较。

### S2-3：报告生成与修订

- [ ] `generate_review` 接受明确 inputRevision，任务键包含 workspace、matchKey、playerKey、输入指纹和规则版本；重复提交返回活动任务或已完成报告。
- [ ] 补全和生成分为可观察的任务；生成固定本地输入，不能计算中途切换到最新快照。
- [ ] 新输入或规则升级后保留旧报告，页面提示“有新数据/规则可重新生成”；点击重算创建新修订，不覆盖旧报告和用户记录。
- [ ] 旧输入的生成任务晚完成时只保存到对应版本，不能覆盖当前新版本指针；报告提交和任务完成在同一短事务中更新。
- [ ] 报告可离线生成；缺少某项静态语义时降级对应规则，图片缺失不阻止基础指标。
- [ ] 实现有界计算并发、取消检查点和中断恢复；单规则错误不使已保存报告不可读。

## 5. 页面和图表

### 5.1 对局列表的增量入口

- [ ] 对局行增加“查看复盘”，可用状态以文字/Badge 表达：未生成、已有报告、有新数据；不为每行发 DETAILS 请求。
- [ ] 进入详情后返回列表保留玩家、筛选、分页和滚动位置；已有复盘标签复用，不无限重复打开。

### 5.2 复盘详情 `/matches/$matchKey/review`

定位参数包含目标 playerKey、可选 reportId/报告修订、证据 ID 和比赛内时间；全部校验。未指定报告时读取最新可用报告；显式旧修订链接必须读旧修订，找不到时提示，不静默跳到最新报告。

页面从上到下包含：

1. 对局概况：英雄、模式、胜负、时长、版本、来源、完整度、目标玩家；提供返回列表、补全、生成/重算及任务取消入口。
2. 复盘概览：核心指标、最多三项优先改进和数据限制，建议卡片可跳转证据。
3. 时间线与图表：个人/对位经济与补刀曲线、死亡/资源/构建事件筛选、准确时间定位；不实现推断视野或实时回放。
4. 笔记与反馈：对局笔记、证据笔记、建议是否有帮助/不准确、采用训练目标入口。

| 状态 | 页面行为 |
| --- | --- |
| 无本地对局或链接无效 | 明确提示，提供回列表，不展示其他对局占位数据 |
| 只有结算 | 显示基础事实及可计算报告，说明时间线相关指标缺失 |
| 时间线部分可用 | 显示已有片段和覆盖范围，缺口为断点，不画成 0 |
| 补全/生成中 | 保留现有内容和旧报告，显示任务状态与取消入口 |
| 失败/等待授权/限流 | 保留缓存，按错误提供操作；遵守 retryAt，不反复自动重试 |
| 当前模式不支持 | 可以阅读事实和笔记，不能生成训练建议或混入目标评估 |
| 新数据可用 | 保留当前修订，明确提示重算；证据不能混用新旧输入 |
| 离线且有报告 | 完整阅读已有报告、定位已有证据、保存本地笔记和反馈 |

复盘标签按玩家键和对局键唯一，报告版本是标签内可恢复定位状态；切号不改写旧标签所属玩家。关闭有未保存笔记的标签时提供保存、放弃、取消，保存失败保留草稿。标签关闭本身不取消后台任务。

新增侧栏“进展”，按玩家展示训练目标、近期指标趋势、基线与后续评估。列表、复盘、进展、设置构成本期业务页面；连接状态和任务仍留在外壳或页内，不另建任务中心。

- [ ] 筛选玩家、队列、位置、补丁和时间范围；展示实际样本数、缺失数、排除原因及缓存覆盖范围。
- [ ] 支持创建、查看、暂停、完成和放弃训练目标；没有目标时说明创建入口，不展示虚构进展。
- [ ] 趋势按同口径数据计算，可比较分组分别展示，补丁或规则变化处明确分段，不跨版本连出连续提升结论。
- [ ] 目标进展可跳转参与评估的具体对局和报告修订；无新样本时显示“等待后续可比对局”。

## 6. 笔记、反馈与训练评估

### S2-4：本地用户记录

- [ ] 笔记绑定对局，可选绑定报告修订/证据；反馈绑定明确 reportId 与 findingId，报告重算不自动转移旧反馈。
- [ ] 使用 SQLite 持久化，通过 Commands 写入；采用 expectedRevision 防止多标签互相覆盖，冲突返回服务器当前修订，保留用户草稿。
- [ ] 文本按纯文本显示，限制长度，不执行昵称、接口文本或笔记中的 HTML/脚本。
- [ ] 支持新增、修改、删除笔记及修改/清除反馈；删除操作明确目标对象，失败不丢草稿。
- [ ] 目标由用户确认采用，不能因为查看报告或点击建议自动创建。

### S2-5：可复算训练闭环

首批目标模板限定为“10 分钟总补刀”和“每 10 分钟死亡数”，均复用已版本化的指标定义。自定义目标先只允许选择已有指标、改进方向和目标值，不支持任意脚本或自然语言自动转规则。

| 项目 | 二期规则 |
| --- | --- |
| 目标范围 | 固定玩家、队列、可靠分路、补丁分组、指标版本；目标创建后不静默改变 |
| 基线 | 创建前最近 10 场合格对局的指标均值；至少 5 场才建立数值基线，不足时只保存草稿并说明原因 |
| 后续窗口 | 创建后开始的最近 10 场合格对局；至少 5 场才计算达标状态，少于 5 场可展示样本但标记不足 |
| 排除 | 重开、模式不支持、关键字段缺失、时长不满足、位置不可靠、补丁或指标版本不可比；逐项统计原因 |
| 结果 | 基线值、当前值、差值、目标值、有效/缺失样本数、窗口起止和成员引用；不宣称统计显著性或建议导致了提升 |
| 修订 | 基线固定输入引用；后续补全可生成新评估修订，旧评估保留。修改指标、范围或阈值创建新目标版本 |
| 生命周期 | draft / active / paused / completed / abandoned；暂停不自动评估，恢复后仅使用恢复时间之后开始的对局作为新的后续窗口 |

“每 10 分钟死亡数”按 `死亡数 / 实际分钟 × 10` 计算，至少达到 10 分钟且非重开才进入该目标样本；不把该指标下降等同于整体表现提升。达到阈值只提示当前窗口达标，目标完成由用户确认。

- [ ] 报告提交后，仅对受影响的 active 目标排队本地评估；任务按目标版本与输入集合去重，不自动请求更多历史 DETAILS。
- [ ] 样本来自本地缓存和固定输入，样本不足时提供返回列表同步/逐场补全入口；不把局部缓存说成完整历史。
- [ ] 保存评估算法版本、成员对局和输入/报告修订、排除原因，保证重启、规则升级和数据补全后仍可解释结果变化。

## 7. 存储、Commands 与一致性

### 7.1 增量迁移

新增迁移，例如 `0002_stage2.sql`，不得修改已发布的一期迁移来伪装升级。生产与 core/harness 复用相同迁移；升级前备份、较新 schema 拒绝、失败恢复沿用一期流程。

| 对象 | 增量职责 |
| --- | --- |
| 快照引用与分析输入修订 | 关联对象、端点类别、抓取元数据、不可变快照集合与规范输入；不覆写历史事实 |
| `reviews` | 玩家、对局、输入指纹、规则版本、报告结构与修订；相同确定性输入唯一 |
| `review_notes` / `review_feedback` | 用户记录、所属对象、乐观锁修订、保存时间；外键保证引用有效 |
| `training_goals` / `goal_evaluations` | 目标版本、基线、范围、生命周期，以及每次评估输入与结果 |
| `jobs` 与活动索引 | 详情/报告/评估的业务去重键、输入修订、阶段、重试时间和结果引用；保留一期任务兼容性 |

时间线仍以不可变 JSON 快照为主，不预先拆成全量事件数据库。不新增 QQ101/reference_snapshots 或模型调用空表。快照、规范输入及报告引用的语义资源属于业务证据，不能随图片缓存清理删除。

- [ ] 从真实一期结构迁移，保留玩家、摘要、设置和历史任务；一期没有时间线/报告的数据迁移后标为缺失，不伪造 ready。
- [ ] 网络等待在事务外；快照引用、输入修订、当前投影和任务检查点在短事务中协调提交，事件仅在提交成功后发送。
- [ ] 备份包含所有新表及证据必需资源；恢复验证 schema、哈希、外键和报告引用完整性，之后更新 workspaceEpoch。
- [ ] 二期能够恢复一期备份并按受控流程迁移；旧应用拒绝二期 schema/备份，不承诺自动降级。
- [ ] 清理图片后仍能读报告、证据和笔记；诊断默认不导出笔记正文、完整战绩或凭证。

### 7.2 新增或扩展的 Commands

下表为拟定契约，实施时在现有 Rust 注册表、生成器、desktop、fixture、harness 中一起接入。读取 Command 只查本地，写入和任务 Command 显式执行。

| Command | 输入与输出 |
| --- | --- |
| `get_match_review_data` | matchKey、playerKey、可选输入修订 → 结算、来源、能力、当前输入/报告和活动任务摘要 |
| `fetch_match_details` | matchKey、playerKey → 经过会话与能力校验的持久化 taskId；重复提交合并 |
| `get_timeline_slice` | 固定输入修订、起止时间、事件类别、游标、有限条数 → 时间片段、覆盖范围、下一游标 |
| `get_match_metrics` | 固定输入修订、指标集合、时间范围、点数预算 → 有界图表系列和缺失说明 |
| `generate_review` / `get_review` | 固定输入生成任务；按 reportId 或对局/玩家/明确修订读取报告 |
| `get_review_evidence` | reportId、evidenceId → 校验归属后的准确原始记录与必要上下文；不接受任意 JSON 路径读取 |
| `save_review_note` / `delete_review_note` | 对象键、文本、expectedRevision → 保存修订或冲突 |
| `save_review_feedback` | reportId、findingId、反馈或清除标记、expectedRevision → 反馈修订 |
| `get_review_annotations` | 对局/玩家及报告修订 → 对局笔记和该报告的反馈/证据笔记 |
| `save_training_goal` / `list_training_goals` | 创建/修改目标版本与状态；按玩家/状态有界分页读取 |
| `get_goal_progress` | 目标版本、可选评估修订 → 基线、当前结果、成员与排除原因的有界列表 |
| `evaluate_training_goal` | 目标版本 → 本地重评任务 ID，不隐式同步远端 |
| `get_player_progress` | 玩家与经校验的范围/分组 → 有界趋势数据、样本量与覆盖范围 |

复用 `get_task_status / cancel_task`。错误沿用现有 `code / params / retryable / requestId / taskId`，按实际需要增加 `DATA_INCOMPLETE`、`ANALYSIS_UNSUPPORTED`、`REVISION_CONFLICT`、`EVIDENCE_UNAVAILABLE`；普通缺项优先表达为能力/指标状态，不把局部缺失变成整个页面异常。

### 7.3 缓存与事件

- [ ] Query key 必须包含 workspaceEpoch、对象键、目标玩家、输入/报告/目标修订及影响结果的筛选；不复用其他玩家占位数据。
- [ ] 复用现有事件信封，增加报告、笔记/反馈、目标/评估变更通知；payload 只带对象键、修订和 taskId，不推完整时间线。
- [ ] 订阅与本地快照对账覆盖启动竞态、乱序、漏发、窗口重载和恢复焦点；事件只加速刷新，不能成为唯一事实来源。
- [ ] 恢复备份清除旧工作区 Query、任务引用、图表和未提交写请求；草稿明确提示工作区已变化，不直接写入另一工作区。

### 9.2 初始资源预算

以下是实现预算与待测目标，不是已达到的性能承诺：

- 沿用每服务最多 2 个网络请求的起始预算，重分析同时 1 个；当前打开对局优先，但队列必须防止历史任务长期饥饿。
- 图表每系列最多约 1,000 点；事件默认每页 100、最大 500，时间区间和 IPC 响应大小受服务端校验，超限返回可分片读取的错误。
- 进度通知每任务最多约 4 次/秒，终态立即发送；前端不缓存所有历史时间线。
- 在记录配置的 Windows 机器上，以 1 万场摘要的列表查询 p95 ≤ 500ms 为基座回归目标；固定常规对局样本的本地复盘查询 p95 ≤ 500ms、报告计算 p95 ≤ 2s 为初始目标，网络等待单独统计。
- 记录冷/热缓存、样本大小/帧数/事件数、报告计算耗时、峰值内存、标签反复切换后的内存趋势及退出等待时间；达不到时说明瓶颈和调整结果，不用 Mac 数字代替 Windows 结论。
