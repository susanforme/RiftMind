# 四期计划 英雄笔记与深度复盘训练

状态：已实现并完成 Mac 开发链路验收。日期：2026-10-19。

实现、验证命令、性能和未验证边界见[四期验收记录](../docs/stage4-verification.md)。真实 Riot/Tencent 客户端写入仍待实机验证，生产门禁保持关闭。

本期方向为英雄笔记、出装方案与深度复盘训练，继续以 Mac 开发链路验收。基于[三期计划](stage3.md)及[三期验收记录](../docs/stage3-verification.md)，用户可以为指定英雄积累连招、对线经验和多套出装，也可以从复盘发现问题、与可比历史比较，再跟踪训练进展。

核心流程：**选择问题 → 查看事件上下文 → 对照个人历史 → 确认训练目标 → 补齐选定样本 → 查看逐场进展**。

英雄笔记流程：**选择英雄 → 记录连招/对线经验/出装 → 赛前查阅或应用装备方案 → 赛后补充心得**。笔记无需先有战绩、报告或连接客户端。

英雄笔记增强按“赛前速查 → 历史与误删恢复 → 轻量练习清单”的产品优先级推进，历史保存随基础编辑一起实现；内容关联、版本复核和单英雄导入导出也纳入本期。

## 1. 范围与既有能力

二期已经提供指标、事件列表、经济与补刀曲线、证据笔记、反馈和训练目标；三期补齐英雄池、两场对比、跨场问题及目标来源。本期新增独立于比赛的英雄笔记，并复用既有复盘和训练能力。

| 必须交付 | 本期不交付 |
| --- | --- |
| 指定英雄的通用笔记、连招、对阵经验及多套出装 | 连招宏、按键模拟、自动施法、笔记社区与云同步 |
| 赛前速查、内容历史与回收站、手动练习清单 | 自动判断连招熟练度、每日打卡与积分体系 |
| 内容关联、版本复核、单英雄笔记导入导出 | 攻略自动抓取、自动推荐系统、导入后自动应用到客户端 |

## 2. 英雄笔记

英雄笔记属于本地工作区的用户知识记录，按稳定的英雄 ID 组织；不同游戏账号可查阅同一份笔记，应用出装时才选择当前连接的账号。以李青为例，用户能分别保存常见连招、对阵某个英雄的经验和多种装备方案。

### 2.1 创建与查阅

- [x] 提供“英雄笔记”入口和全英雄搜索；没有本地比赛的英雄也能创建，英雄池、复盘页和比赛阵容中的英雄入口可以跳转到对应笔记。
- [x] 英雄详情按“笔记、连招、对线、出装”组织；支持新建、编辑、删除、搜索及置顶。同一英雄每类可保存多条，只有标题和必要内容必填。
- [x] 保留自由文本记录，用户不必把所有心得塞入固定模板。界面标签国际化，用户原文不自动翻译或改写。
- [x] 支持显式保存及保存状态；切页或关闭编辑器时保护未保存草稿，保存失败和修订冲突保留输入，不静默覆盖另一标签的编辑。
- [x] 离线可读取和编辑已保存内容，重启后保留；首次英雄目录与资源未缓存时如实显示不可用，不要求连接 LoL 才能读笔记。
- [x] 可从对局笔记创建英雄笔记并附上来源；来源包含固定对局/报告/证据引用，原笔记保持独立，后续编辑不双向自动同步。
- [x] 删除来源对局前处理关联关系；保留用户写入的笔记正文，来源不可用时明确显示，不级联删除英雄知识记录。

### 2.2 连招

- [x] 保存连招名称、步骤顺序、适用场景和操作要点；步骤可选择 Q/W/E/R、普攻、召唤师技能、装备主动效果或自由文本动作。
- [x] 英雄技能步骤显示对应技能图标和按键；支持首段/二段等用户标注，能表达李青的 Q1/Q2、W1/W2。普攻、移动等动作使用明确文字，不能借用无关游戏图片。
- [x] 步骤支持插入、删除和重排，提供键盘与按钮操作；不要求拖动才能编辑。
- [x] 用户可只写文字连招，结构化步骤为可选增强；不校验其一定可执行，不自动测算伤害，也不执行连招。

### 2.3 对阵经验

- [x] 对阵记录绑定“我方英雄 + 对方英雄”，可选位置、补丁和标签；双方都展示头像，支持按对方英雄筛选。
- [x] 正文可记录对线、野区交锋、换血时机及装备取舍，同一组合允许保存多条经验。
- [x] 从当前公开阵容进入时，仅提供相关笔记入口；对方位置不确定时不宣称其为实际对位，不反查匿名身份，不自动弹窗抢占页面。
- [x] 经验标为用户记录，不能作为系统已验证的克制关系或训练指标；需要量化评估时仍使用已有确定性指标。

### 2.4 多套出装

- [x] 一名英雄可保存多套命名方案，含适用地图、可选位置/对手/补丁、使用条件与自由备注。
- [x] 通过带图片的装备搜索添加装备，按出门装、首次回城、核心装、备选装等可重命名分组保存顺序和数量；分类由用户调整。
- [x] 本地保存装备 ID 与明确的资源版本；旧方案不随补丁静默替换装备。应用或导出前按目标版本/地图检查，缺少目录、装备失效或不可购买时说明具体项，不发送未经校验的方案。
- [x] 方案可复制后修改；从实际对局出装保存为草稿时保留来源，由用户确认分组及用途，不宣称这是推荐最优出装。
- [x] 提供客户端装备方案 JSON 导出作为独立能力；导出只包含兼容的英雄、地图和装备分组字段，私有心得、对线正文及证据引用默认不导出。

### 2.5 赛前速查

- [x] 比赛页提供用户主动打开的速查面板，按当前选定英雄展示置顶笔记、常用连招、对阵经验及出装；未选英雄时允许手动选择。
- [x] 对方公开英雄可作为对阵筛选条件；默认先显示用户置顶内容，不生成克制结论或出装推荐。
- [x] 换英雄、取消选人、切号和新比赛时更新上下文，不混用上一局阵容；打开的笔记和未保存草稿不被自动替换，退出比赛后仍可手动查阅。
- [x] 速查复用笔记本内容，不保存另一份副本；展示头像、技能序列、装备图片和必要标签，长正文按需展开，无内容时提供创建入口。
- [x] 不自动弹窗、切标签或写入客户端。用户仍须选择具体出装并点击应用，沿用第 3 节的阶段与权限门禁。

### 2.6 内容历史与误删恢复

- [x] 通用笔记、连招、对阵经验和出装每次成功保存均保留不可变修订，包含正文或结构化内容、关联关系、版本复核状态及保存时间；不以每次按键创建历史。
- [x] 可查看历史版本并恢复，恢复操作产生一个新修订，保留恢复前内容；采用修订校验，遇到其他标签的新修改时保留草稿并提示冲突。
- [x] 删除先进入回收站，默认列表、搜索和速查排除已删除内容；恢复后保留原 ID、历史及可恢复的关联关系。
- [x] 本期不自动清空回收站或裁剪历史；永久删除需明确确认其内容与引用影响。其他笔记和练习项不级联删除，失效引用可解除或重新关联。
- [x] 恢复或删除本地出装均不修改已写入客户端的方案；历史与回收站纳入整库备份和恢复。

### 2.7 轻量练习清单

- [x] 从连招或笔记创建练习项，保存英雄、标题、关联内容、手动状态及练习心得；状态为“待练习、练习中、已掌握”，允许重新进入练习。
- [x] 入口位于英雄笔记，进展页可按英雄查看；使用紧凑清单，不新增独立训练首页、连续打卡、积分或提醒系统。
- [x] 状态与心得由用户手动更新，不通过胜率、KDA 或时间线自动推断熟练度；与数值训练目标分开存储和呈现，不计入其达标统计。
- [x] 关联连招更新后保留既有状态和心得，并显示内容已变化；删除来源不丢失练习记录，用户可重新关联或删除练习项。

### 2.8 笔记与方案关联

- [x] 笔记、连招、对阵经验与出装之间可建立和解除显式关联；一条对阵经验可关联多条连招、多套出装和多场复盘，不复制被关联正文。
- [x] 本地知识内容链接默认打开当前有效修订，历史内容中保留当次引用的修订以便追溯；比赛、报告和证据链接始终固定原修订。
- [x] 被关联内容更新后显示最新内容；进入回收站或永久删除时分别显示可恢复/不可用状态，不静默指向同名记录，不产生级联删除。
- [x] 关联仅用于导航，不递归展开全文、不触发自动写入，循环关联不得导致加载循环。

### 2.9 版本复核

- [x] 笔记、连招、对阵经验和出装可记录用户最后确认适用的补丁；与图片资源版本、内容修订和系统分析规则版本分开保存。
- [x] 对照明确的目标补丁筛选“未标注、待复核、已确认”内容；目标补丁来源可为已识别客户端或用户手动选择，未知时不猜测。
- [x] 用户可标记“仍适用”或编辑后确认，复核动作产生可追溯修订；不因补丁变化自动认定经验失效，也不批量弹窗提醒。
- [x] 内容修改后保留历史复核记录，除非本次明确确认适用版本，否则当前修订标为待复核；来自他人的导入内容不视为本机用户已确认。
- [x] 出装的用户复核不能代替装备 ID、目标版本和地图可用性校验，标记“仍适用”不能绕过第 2.4 节的应用检查。

### 2.10 单英雄笔记导入导出

- [x] 提供独立、版本化的英雄笔记 JSON 文件，支持导出所选英雄的通用笔记、连招、对阵经验、出装及内部关联；与客户端装备方案 JSON 使用不同的格式标识和操作名称。
- [x] 导出前显示包含哪些条目，默认导出当前有效内容，不含历史、回收站、练习心得、账号信息、客户端 UID 映射或对局私有数据。整库备份继续负责完整恢复。
- [x] 跨英雄链接及对局来源只保留经预览确认的非敏感说明，不自动附带其他英雄笔记或原始战绩；导出文件不包含凭证、远端写入任务或可执行内容。
- [x] 导入先校验格式版本、大小、条目数、文本长度和结构化实体 ID，预览新增、重复、冲突及缺失引用；不依赖网络获取任意文件或执行嵌入内容。
- [x] 不按标题自动覆盖；重复内容默认跳过，冲突内容默认另存为新条目，替换已有内容必须显式选择并保存旧修订。明确区分未知英雄 ID 与本地尚未缓存的资源。
- [x] 成功导入时重新映射条目 ID 和内部关联，在单个事务中提交；失败或取消不留下半份笔记。缺失的外部来源显示不可用，装备兼容性在应用时重新验证。
- [x] 导入不恢复客户端方案映射，不自动应用出装，不改变练习状态或数值训练目标；对较新且不支持的文件版本明确拒绝，保留原文件。

## 3. 将出装应用到客户端

### 3.1 已核实的能力与边界

Riot 官方说明，装备方案可关联英雄和地图、按用途分组，并支持同一英雄多套方案，在局内商店使用。[官方装备方案说明](https://support.riotgames.com/en-us/league-of-legends/gameplay/item-sets/)

Riot 的 League Client API 文档说明，该接口在桌面本地运行，不正式支持第三方使用，也不保证完整文档或变更通知；官网这一节没有装备方案的完整读写契约。`127.0.0.1:2999` 的 Game Client API 属于另一类接口，不能当作出装写入接口。[官方 LCU 文档](https://developer.riotgames.com/docs/lol#league-client-api)

开源项目明确列出了以下装备方案读写路径，可作为适配研究起点；这是该项目的实现说明，不是 Riot 的稳定接口承诺，也不证明国服当前可用。[league-lean 的 LCU 端点清单](https://github.com/Nicetyone/league-lean#lcu-endpoints-used)

| 用途 | 待目标客户端核验的路径 |
| --- | --- |
| 获取当前身份 | `GET /lol-summoner/v1/current-summoner` |
| 读取装备方案集合 | `GET /lol-item-sets/v1/item-sets/{summonerId}/sets` |
| 写入装备方案集合 | `PUT /lol-item-sets/v1/item-sets/{summonerId}/sets` |

“应用到客户端”指保存用户选择的装备方案，供局内商店查看和选择；不承诺自动切换为商店当前方案，不购买装备或操作游戏。仅参考端点和数据模型，不引入客户端注入插件。

### 3.2 写入流程

- [x] 方案详情提供“应用到客户端”，旁边显示目标账号和方案名称；用户点击即授权本次应用，常规重复操作不增加多余确认。没有已登录客户端时保留本地编辑与导出。
- [x] Rust 复用现有 LCU 连接，执行能力、当前身份、会话代次与工作区检查；身份 ID 从当前客户端取得，不能把 PUUID、accountId 与 summonerId 混用。
- [x] 首次适配核验实际集合结构、装备方案标识及写入语义，保存脱敏样本和来源版本。未知响应形状停止写入，不能当成空集合覆盖。
- [x] 先读取完整现有集合，只新增或更新本应用明确关联的方案；用本地方案 ID 与账号/区服、远端 UID 建立映射，不按标题匹配，不删除其他方案。
- [x] 集合整体写回时保留其他方案及未知字段，并串行化本应用写入；写前重新检查集合与身份，检测变化就重新读取。若目标接口无条件写入/版本锁，记录其并发窗口，不能宣称能阻止其他程序同时修改。
- [x] 已关联方案被用户在客户端修改时，保留其修改并提供“另存为新方案”或明确覆盖选择；普通应用不覆盖来源不明的方案。
- [x] 写后读取确认 UID、英雄、分组及装备一致，确认后才显示已应用。超时或断连时先对账再允许重试，避免重复生成；不能确定结果时显示待确认。
- [x] 切号、切区、断开、恢复备份后旧请求不得继续写入；只在已验证的赛前阶段开放应用，加载中或比赛中不排队补写。
- [x] 本地删除方案不自动删除客户端方案，恢复备份也不重放写操作；应用失败不影响笔记、出装保存和导出。
- [x] 只通过专用 typed Command 暴露应用动作，前端不接收凭证，不提供任意 LCU 路径或请求体代理。

### 3.3 Mac 验收与真实可用状态

本期交付本地笔记、导出、LCU 适配和完整模拟服务验证。真实客户端可用状态单独记录：能力门禁须结合已验证的客户端/区服适配及当前会话探测；未经实机验证的写入路径不标为可用。条件不足时保留导出，不用模拟成功充当“一键应用已实测”。Windows 实机和客户端版本兼容性仍不阻塞本期 Mac 开发验收，但必须明确区分“适配实现完成”和“真实客户端应用通过”。

## 4. 关键事件复盘

在现有复盘页增加事件上下文视图，沿用原始事件和固定报告引用，不另建一套报告。

- [x] 提供本人死亡和资源事件两种入口；从跨场问题进入时，定位到其报告及证据对应的事件。
- [x] 默认查看事件前后各 60 秒，裁剪至实际比赛范围；支持调整时间范围、上一事件和下一事件。
- [x] 同步高亮经济/补刀曲线、事件列表及证据；返回时保留玩家、对局、报告修订、筛选和时间位置。
- [x] 死亡展示时间、击杀者、助攻者及可靠识别的敌方打野参与情况；未知身份或位置不推断。参与英雄显示对应头像。
- [x] 资源事件展示资源类型、可确认的归属和窗口内相关死亡。只描述时间顺序，不将相关性解释为因果。
- [x] 展示窗口内装备变化和技能升级时复用既有事件能力及游戏图片；购买撤销、出售、重复事件和未知类型保持可追溯。
- [x] 数据不完整时显示已有事件及缺失范围；缺少帧不插值补造经济或补刀变化，曲线断点不连接为连续事实。
- [x] 笔记与反馈继续绑定固定报告/证据；资料补全或规则升级后，旧链接仍能打开原始依据。

首版不新增死亡热力图或走位轨迹。当前规范化输入尚未建立经过验证的地图坐标能力，这类展示不能作为本期完成条件。

## 5. 个人历史基准

复盘页允许把本场指标与自己的此前对局比较。该基准用于阅读复盘；训练目标仍保留单独冻结的基线，两者不能混用。

- [x] 默认范围为同玩家、同队列、同位置、同补丁、同英雄；用户可明确切换为同位置全部英雄，并显示当前范围。
- [x] 仅选择早于当前对局的本地历史数据，排除当前对局、重开、位置不明及指标不可用的记录。
- [x] 每项指标最多选取最近 20 场有效记录；候选扫描范围及截断状态明确返回，不能声称覆盖全部历史。
- [x] 首批使用已有指标：10/15 分钟补刀、10/15 分钟经济差、每分钟补刀、每十分钟死亡。对位指标继续要求可靠的位置匹配。
- [x] 按指标独立计算样本数、中位数和四分位范围；至少 5 场才显示基准与差值。五场是本期产品门槛，不代表统计显著性。
- [x] 四分位算法、样本选择顺序、单位和舍入规则固定并版本化；不把跨版本或不同单位的指标混在一起。
- [x] 用 ECharts 展示本场值和历史分布，提供可访问的数值表；样本过少时展示缺失原因，不给出优劣标签。
- [x] 能逐项查看入选对局、排除原因和对应输入/报告修订；每场仅采用一个明确修订。
- [x] 一次比较固定样本成员及修订，晚到数据不静默替换结果；显式刷新才重新选样。若写入训练来源，则保存可恢复的固定引用。

不以胜负筛选默认基准，也不使用当前对局之后的样本评价历史表现，避免把筛选偏差隐藏在“个人水平”中。

## 6. 训练范围与进展

扩展现有目标和评估机制，使用户看清训练对象、参与评估的对局，以及指标变化发生在哪一场。

- [x] 给训练范围增加可选英雄约束，并贯穿草稿、基线选样、后续评估、查询、UI 和备份。来源中选择了某个英雄时，草稿默认使用同一英雄范围。
- [x] 旧目标缺少英雄约束时继续按原来的全部英雄范围解释；不得根据旧来源筛选反向改变历史目标含义。
- [x] 保留基线/后续各最多 10 场、至少各 5 场才进行数值达标评估的规则；未达门槛可查看逐场记录，不提前显示达标。
- [x] 目标详情使用 ECharts 展示逐场值、冻结基线与目标线；可跳转到每场固定报告及关联事件，保留数值表。
- [x] 分别展示有效样本、缺少详情、尚未生成报告、不适用及版本不匹配；仅在候选范围已知时给出可补全数量。
- [x] 范围、方向或阈值变更形成新目标版本，旧目标、旧基线和旧评估可查看；补丁变化不自动合并样本。
- [x] 暂停、恢复和完成沿用现有流程；明确暂停期间对局是否入样，并用固定案例验证原有语义，避免界面和后端规则不同。
- [x] 新报告产生后，只刷新符合目标范围的评估；旧评估保留成员和版本。达到阈值不自动将目标改为完成。

不新增每日打卡、积分、任务商城或独立训练首页。数值训练入口继续位于复盘页和进展页；第 2.7 节的手动练习清单从英雄笔记进入，并与自动数值评估区分。

## 7. 有限批量样本准备

在战绩列表和训练缺样本入口复用同一批处理能力，解决逐场打开、补详情、生成报告的重复操作。

- [x] 用户显式勾选对局，单批最多 20 场；开始前列出已有报告、可本地生成、需请求详情及不可访问的数量。
- [x] 首版远端批量补全只开放给当前已连接账号本人；离线可对已有合格输入生成报告。他人数据继续沿用现有单场权限门禁。
- [x] 仅处理确认时固定的对局集合；界面筛选变化或新战绩到达不扩展本次任务。
- [x] 复用现有任务调度、限流、请求去重及重试策略，每个远端服务最多 2 个并发；不新增独立后台同步体系。
- [x] 分别记录每场详情获取与报告生成结果；一场失败不回滚其他成功结果。取消停止未开始项，在安全点处理在途项。
- [x] 权限拒绝、授权过期和限流遵守原有来源策略与冷却时间，不以换源或持续重试绕过门禁。
- [x] 同一输入与规则版本不重复生成报告；已有不同修订时明确提供重算动作，保留旧报告、笔记和反馈。
- [x] 进程退出后保留批次及逐场结果；重启标记未完成项，用户主动继续时只处理未完成项并重新检查身份、权限和工作区。
- [x] 完成后刷新问题汇总和相关训练评估，不自动采用目标或抢占当前标签。

该能力是用户主动、范围固定的批处理，不改变三期“打开聚合页面不自动拉取历史 DETAILS”的约束。

## 8. 工程与界面要求

- 继续以 Rust 为契约与计算权威，复用 SQLite、任务、Query 缓存及事件对账；前端不独立计算另一套基准或评估结果。
- 按职责扩展 `champion-notes`、`builds`、`review`、`analysis`、`progress`、`matches` 等业务模块。新增文件如 `ChampionNotebookPage.tsx`、`ComboEditor.tsx`、`ItemBuildEditor.tsx`、`ReviewEventContext.tsx` 使用业务名称，禁止 `Stage4Page` 或阶段编号目录。
- 修改不合规命名时同步导入、导出、测试和国际化资源；不进行与本期功能无关的整库重构。
- 数据迁移按领域增量拆分，例如 `0004_champion_notebooks.sql`、`0005_review_training_insights.sql`，实施时核对实际序号；同步 core、harness、生产迁移注册及生成契约，保留已存在迁移内容和历史兼容语义。
- 英雄笔记、连招步骤、对阵记录、出装分组及客户端方案映射属于 SQLite 业务数据，含修订及更新时间；笔记不依赖游戏账号外键，映射明确绑定账号/区服。旧备份升级为空笔记库，新备份完整保存内容，恢复后的远端映射必须重新核验。
- 内容修订、回收站状态、内部关联、版本复核和手动练习项同样纳入 Rust 契约、SQLite 迁移及整库备份；历史恢复和导入使用事务及修订检查。导入文件格式独立版本化，客户端映射不进入可交换的笔记文件。
- 保存训练范围、基准引用和批处理记录时，备份恢复需验证关联关系；恢复后不自动继续旧网络任务，旧工作区任务不得写入新工作区。
- UI 组合 shadcn/ui，缺失组件通过官方 CLI 添加；图表统一使用 ECharts，按需加载并释放实例。
- 沿用现有侧栏、顶部标签、配色和字体；英雄笔记使用头像导航、技能序列与装备分组，复盘页优先展示曲线及事件，进展页优先展示目标及趋势，详细依据按需展开。UI 文案精简规则不限制用户自行撰写的长笔记。
- 英雄、装备、召唤师技能及英雄技能使用对应图片，预留尺寸并提供可访问名称及失败回退。
- 支持简中/英语、浅色/暗色/跟随系统、800×600 最小窗口、键盘操作及减少动态效果；图表含单位、样本数、空数据状态和数值表。
- 不增加介绍段落、装饰性副标题或实现说明；保留必要的数据不足、错误与可比性信息。

另加英雄笔记 E2E：搜索李青 → 创建连招 → 选择对阵英雄并保存经验 → 编辑两套装备方案 → 导出 → 模拟 LCU 应用且保留既有方案 → 复盘补充来源 → 备份恢复及离线重启。JSON 导出使用独立核对的客户端格式样本，真实客户端导入/商店可见性另行记录。

补充笔记使用与保护 E2E：关联对阵经验和出装 → 赛前打开速查并切换英雄 → 创建练习项及手动记录心得 → 修改并恢复历史 → 删除后从回收站恢复 → 对新补丁标记仍适用 → 导出单英雄笔记 → 在独立工作区预览导入并验证重复导入 → 离线重启校验内容及关联。必须断言笔记导入、恢复和速查本身没有触发客户端写入。

性能使用固定 Mac 环境和明确数据规模记录冷/热查询、事件窗口加载、20 场批处理耗时及取消延迟；聚合继续覆盖至少 10,000 场摘要，同时补充有足够报告和时间线的样本。S4-0 记录基线后固定验收预算，不把网络模拟耗时当作真实网络性能。

验收脚本按业务命名，例如 `scripts/verify-review-training.ts`；如保留 `verify:stage4` 作为阶段入口，仅作为文档命令别名。完整命令、环境、结果与限制写入 `docs/stage4-verification.md`。
